# R Design Space · агент лидогенерации

Бот ищет стартапы и SaaS по миру, отбирает их ИИ, пишет письмо на языке фаундера и присылает карточку в Telegram.
Письмо уходит **только после нажатия кнопки «Отправить письмо»**. Постоянный сервер не нужен.

```
Telegram ──► Vercel api/telegram.js ──► GitHub Actions (outreach.yml) ──► scraper.py ──► Telegram
 /search        webhook, мгновенно         workflow_dispatch               поиск, ИИ,       карточки
 кнопки         проверяет секрет и chat id  (search | send)                письмо, Gmail    и отчёт
```

## Файлы

| Файл | Назначение |
|---|---|
| `api/telegram.js` | webhook: команды, диалог с памятью, кнопки; запускает Actions |
| `api/_lib/memory.js`, `store.js`, `claude.js` | долговременная память, её хранилище (приватный репозиторий), клиент Claude |
| `.github/workflows/outreach.yml` | ежедневно 09:00 UTC + запуск из Telegram; сохраняет `tracker.json` и `pending.json` |
| `agent/scraper.py` | точка входа: `--action search \| send`, `--query`, `--lead-id` |
| `agent/qualifier.py` | жёсткий отбор (порог 7/10), анализ на русском, определение языка письма |
| `agent/pitch_writer.py` | письмо на языке фаундера в стиле R Design Space |
| `agent/email_sender.py` | Gmail SMTP, подпись и отписка на языке письма |
| `agent/telegram_bot.py` | карточки, кнопки, отчёт, тексты `/start` и `/help` |
| `agent/bot_poll.py` | необязательный локальный режим polling (вместо webhook) |
| `agent/set_webhook.py` | разовая регистрация webhook и меню команд |
| `agent/llm.py`, `agent/langs.py` | клиент Claude/OpenAI, справочник языков |
| `agent/config.json` | ключевые слова, регионы, лимиты, `require_confirmation` |
| `agent/tracker.json`, `agent/pending.json` | обработанные лиды и черновики, ждущие кнопки |

## Какие лиды остаются

Только **явные запросы на дизайн и разработку интерфейса**: заказчик, которому нужны дашборд, CRM или админка, веб-приложение,
личный кабинет, редизайн интерфейса, многостраничный сайт, лендинг или дизайн-система.

- **Отсекается до ИИ** (без расхода запросов): инвестиции, раунды, фандрайзинг, оценки, поглощения и IPO на английском,
  русском, немецком, французском, испанском, португальском, турецком, японском, корейском и китайском. Пост, который
  упоминает раунд, но прямо просит дизайнера или разработчика, остаётся.
- **Отсекает ИИ** (`intent`): анонсы продуктов без просьбы о помощи, общие новости стартапов, библиотеки, хобби, найм
  не по профилю (бэкенд, ML). Принимается только `explicit_request` с типом задачи не `none` и оценкой не ниже 7.
  Политику проверяет код, а не ответ модели: если модель сама напишет `relevant: true` для анонса, лид всё равно отсеется.
- **Источники по умолчанию:** Hacker News (Ask HN и Show HN за последние 24 часа). Ленты новостей (Google News, vc.ru,
  EU-Startups) и Product Hunt в основном дают анонсы и новости, поэтому выключены: `global_search.enabled=false`,
  `extra_feeds=[]`, `producthunt_feed=""`. Включить обратно можно в `config.json`.

## Письмо

Короткое (70–110 слов), уверенное, от лица Рустама / R Design Space, на английском. Структура: боль клиента своими словами
с деталью из его поста, конкретное решение (UX/UI дашборда, интерфейс кабинета, дизайн-система, конверсионный лендинг)
в виде экранов, сценариев, компонентов и Figma-кита, строка о специализации и один следующий шаг.

## Источники (по всему миру)

Product Hunt, Hacker News (Show HN и Ask HN), **Google News RSS** на 15 регионов и языков (США, Великобритания,
Россия, Казахстан, Германия, Франция, Испания, Латинская Америка, Бразилия, Турция, Индия, Сингапур, Япония,
Корея, Тайвань), vc.ru и EU-Startups. Регионы и запросы правятся в `config.json → global_search`.
Для новостных лидов сайт неизвестен, поэтому по ним приходит карточка для ручного контакта; письма
автоматически готовятся там, где найден публичный email на сайте продукта.

## Настройка (один раз)

1. **GitHub → Settings → Secrets and variables → Actions → Secrets:** `ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`,
   `TELEGRAM_CHAT_ID`, `GMAIL_APP_PASSWORD`. Variables: `DRY_RUN=true` (на `false` только после проверки карточек).
2. **Токен для запуска Actions из Vercel:** GitHub → Settings → Developer settings → Fine-grained tokens →
   только этот репозиторий, право **Actions: Read and write**.
3. **Vercel → Project → Settings → Environment Variables:** `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
   `GH_DISPATCH_TOKEN` (токен из п. 2). `TELEGRAM_WEBHOOK_SECRET` больше не нужен: секрет вебхука вычисляется из токена бота. После этого Redeploy.
4. **Регистрация webhook** (локально, один раз):
   `python agent/set_webhook.py https://<проект>.vercel.app/api/telegram`
5. Напишите боту `/start`, затем `/search`.

Без Vercel: `python agent/bot_poll.py` слушает команды прямо на вашем компьютере (пока окно открыто).

## Память и диалог

Любое сообщение без «/» — вопрос ассистенту (Claude). Перед ответом бот читает память: активные проекты, записи
по теме вопроса (даже недельной давности) и последние реплики; после ответа сохраняет новое — проекты и документы
(например, по спортивным клубам), договорённости со сроками (даты переводятся в `ГГГГ-ММ-ДД`), интересы. Пароли,
токены и ключи не сохраняются никогда.

| Команда | Что делает |
|---|---|
| `/memory` | активные проекты, договорённости, интересы |
| `/memory клуб` | поиск по памяти |
| `/history 15` | последние записи по времени |
| `/remember <текст>` | сохранить заметку сразу |
| `/forget <id>` | удалить запись (id в скобках в `/memory`) |

**Где лежит память.** Файл `memory.json` в **отдельном приватном** репозитории (API GitHub, база и сервер не нужны).
Репозиторий с кодом публичный, поэтому хранить в нём личные диалоги нельзя: код отказывается писать в любой
не приватный репозиторий.

Настройка:
1. Создайте **приватный** репозиторий, например `r_design_space_memory` (можно пустой).
2. Fine-grained токен GitHub: доступ к двум репозиториям — код (**Actions: Read and write**) и память
   (**Contents: Read and write**). Один токен может быть и в `GH_DISPATCH_TOKEN`, и в `GH_MEMORY_TOKEN`.
3. Vercel → Environment Variables: `ANTHROPIC_API_KEY`, `MEMORY_REPO=<владелец>/r_design_space_memory`,
   `GH_MEMORY_TOKEN` (опционально `CHAT_MODEL`, `MEMORY_PATH`). Redeploy.
4. Повторно выполните `python agent/set_webhook.py https://<проект>.vercel.app/api/telegram` — обновится меню команд.

Диалог и память работают только в режиме webhook; локальный `bot_poll.py` умеет `/search` и кнопки писем.
Файл схемы и логика: `api/_lib/memory.js` (поиск, запись, секреты), `api/_lib/store.js` (хранилище),
`api/_lib/claude.js` (запрос к Claude).

## Безопасность

- Бот подчиняется только вашему `TELEGRAM_CHAT_ID`; webhook проверяет секретный заголовок Telegram.
- Память хранится только в приватном репозитории; в публичный бот не пишет (`MEMORY_ALLOW_PUBLIC` не включайте).
- Текст запроса передаётся в workflow через переменные окружения, а не в команду shell.
- Письмо = одно на домен, с отпиской; `DRY_RUN` блокирует реальную отправку даже после нажатия кнопки.
- Если подряд нажать «Отправить» у нескольких лидов, GitHub оставляет в очереди только последний запуск;
  нажмите кнопку у пропущенного письма ещё раз.
